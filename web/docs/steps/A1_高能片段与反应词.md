# A1 高能片段与自动反应词 — 实现步骤

## 1. 功能需求

- 从弹幕时间分布里自动找出"高能片段"（精彩时刻），吸收 4 个同类项目升级点：
  ① 自适应窗口  ② z-score 判定  ③ 重叠容差  ④ 佐证弹幕
- 按视频自动生成"反应词"（短词 + 高频 + 时间扎堆），替代写死的词表

## 2. 技术选型

- 纯 Python（`statistics` + `collections.Counter`），千级弹幕无需 pandas
- 借鉴同类项目：emoekg（自适应窗口 + 佐证弹幕）、论文《众包直播精彩片段识别》（z-score）、
  auto-slice-video（重叠容差合并）

## 3. 实现思路（算法逻辑总览）

高能片段五步走：
```
离散化（分桶，缺桶补0） -> z-score 判热桶 -> 连续热桶合成段
   -> 段间相距<=容差就合并 -> 每段补峰值秒 + 佐证弹幕
```

反应词三步走：
```
统计每个短词的出现时间 -> 双指针滑窗找"峰值窗口内条数"
   -> 算密度比 burstiness，超过阈值才算反应词
```

> 第 4 节每个函数都有代码 + 逐步讲解。

## 4. 具体代码实现

### 4.1 adaptive_window —— 自适应窗口

```python
def adaptive_window(duration_sec):
    if duration_sec < 300:
        return 15
    if duration_sec <= 1800:
        return 30
    return 60
```

**讲解**：三档窗口。为什么按时长分档？
- 短视频(<5min)弹幕本来就少，窗口太大高潮被"摊平" -> 15s
- 半小时内用 30s（本项目测试视频 1529s 落这一档）
- 长视频用 60s，否则单桶弹幕太少、全是噪声

### 4.2 _bucketize —— 时间分桶（缺桶补 0）

```python
def _bucketize(records, window_sec):
    counter = Counter()
    for r in records:
        sec = int((r.get("progress_ms") or 0) / 1000)
        counter[sec // window_sec] += 1
    max_bucket = max(counter) if counter else 0
    return [
        {"start": i * window_sec, "end": (i + 1) * window_sec, "count": counter.get(i, 0)}
        for i in range(max_bucket + 1)
    ]
```

**讲解**：
1. `sec // window_sec`：把秒数转成桶编号（75s / 30s = 桶2，即 60-90s）
2. `Counter` 只记录"有弹幕的桶"，所以 `max_bucket` 是最后一个有弹幕的桶
3. 关键：`for i in range(max_bucket + 1)` 遍历**从 0 到最后一个桶的全部桶**，
   `counter.get(i, 0)` 对没有弹幕的桶补 0。
   **为什么要补 0**：不补的话"沉默的 30 秒"不参与统计，mean/std 被抬高，
   z-score 就失真，高潮反而不突出。

### 4.3 _z_hot_buckets —— z-score 判定

```python
def _z_hot_buckets(buckets, z_thresh=2.0, min_density=None):
    counts = [b["count"] for b in buckets]
    mean = sum(counts) / len(counts) if counts else 0
    std = statistics.pstdev(counts) if len(counts) > 1 else 0
    if min_density is None:
        min_density = max(2, round(mean))
    hot = []
    for b in buckets:
        z = (b["count"] - mean) / std if std > 0 else 0.0
        if z >= z_thresh and b["count"] >= min_density:
            hot.append(b)
    return hot, mean, std
```

**讲解**：
- `z = (count - mean) / std`：衡量"这个桶偏离平均几个标准差"
- 判定条件两个（AND）：
  1. `z >= 2.0`：明显高于平均（正态分布下 z>=2 约占前 2.5%）
  2. `count >= min_density`：绝对下限，防 std≈0（弹幕太均匀）时 z 爆炸误报
- 代入测试视频（30s 桶，mean=26.8，std=5.4）：
  - 60-90s 桶 count=43，z=(43-26.8)/5.4=3.0 -> 热桶
  - 150-180s 桶 count=15，z=(15-26.8)/5.4=-2.2 -> 冷桶
- `statistics.pstdev` 是**总体**标准差（除 n），`stdev` 是样本（除 n-1），这里用总体

### 4.4 hot_segments_v2 —— 主流程（合并逻辑）

```python
    # ① 连续热桶 -> 桶级段
    runs = []
    for b in hot:
        if runs and b["start"] == runs[-1]["end"]:
            runs[-1]["end"] = b["end"]
            runs[-1]["count"] += b["count"]
        else:
            runs.append({"start": b["start"], "end": b["end"], "count": b["count"]})

    # ② 段间相距 <= merge_gap_sec 就合并（重叠容差）
    merged = []
    for s in runs:
        if merged and s["start"] - merged[-1]["end"] <= merge_gap_sec:
            merged[-1]["end"] = s["end"]
            merged[-1]["count"] += s["count"]
        else:
            merged.append(dict(s))
```

**讲解**（merge_gap_sec 默认 = window_sec // 2，30s 窗口下是 15s）：
- ① 遍历热桶，若当前桶的 start 等于上一段的 end（紧挨着）就并入，否则开新段。
  测试数据热桶 start=[0,30,60,120]：0-30-60 连成 [0-90]，120 开新段 [120-150]
- ② 遍历段，若当前段 start 减去上一段 end <= 15s 就合并。
  这里 [120-150].start(120) - [0-90].end(90) = 30 > 15 -> **不合并**，保持两段。
  这就是"重叠容差"：两个挨得很近的爆发算同一高潮，中间有明显沉默就分开
- 每段再算 `peak_sec`（段内 count 最大的桶的中心秒）和佐证弹幕，按 count 降序取 top_k

### 4.5 _segment_evidence —— 佐证弹幕

```python
def _segment_evidence(records, start_sec, end_sec, n=5):
    counter = Counter()
    first_seen = {}
    sample = {}
    for r in records:
        sec = int((r.get("progress_ms") or 0) / 1000)
        if start_sec <= sec < end_sec:
            content = (r.get("content") or "").strip()
            if not content:
                continue
            counter[content] += 1
            first_seen.setdefault(content, sec)
            sample.setdefault(content, r)
    return [
        {"content": text, "count": cnt, "color": sample[text].get("color", 0),
         "mode": sample[text].get("mode", 1), "first_seen_sec": first_seen[text]}
        for text, cnt in counter.most_common(n)
    ]
```

**讲解**：只统计 `[start, end)` 区间内的弹幕，**按内容去重计数**，
取出现最多的前 n 条。为什么去重计数而不是随机采样？
因为要回答"观众那一刻**集体**刷了什么"，重复多的才是集体反应。
`setdefault` 保留每条内容第一次出现的秒数/颜色/模式，供页面渲染。

### 4.6 _max_count_in_window —— 双指针滑窗（核心技巧）

```python
def _max_count_in_window(times, window_sec):
    left = 0
    best = 0
    for right in range(len(times)):
        while times[right] - times[left] > window_sec:
            left += 1
        best = max(best, right - left + 1)
    return best
```

**讲解**：`times` 是某词出现秒数的**有序列表**（先 sort）。
- `right` 指针往前走，`left` 指针收缩，保证 `[left, right]` 全部落在 window_sec 内
- `right - left + 1` 就是当前窗口内的条数，`best` 记录最大值
- 复杂度 O(n)：每个指针最多走一遍，比"每点开一个窗口"的 O(n*w) 快
- 例：times=[697,710,714,723,736,738,742,751]，window=30，
  从 723 开始 751-723=28<=30，窗口能装 723..751 共 4 条 -> 30s 内最多 4 条

### 4.7 auto_reaction_words —— 反应词判定

```python
        secs.sort()
        n = len(secs)
        peak_in_window = _max_count_in_window(secs, window_sec)
        if peak_in_window < 2:                       # 峰值窗口内至少 2 条
            continue
        avg_rate = n / max(duration_sec, window_sec) # 全片平均密度
        burst = (peak_in_window / window_sec) / avg_rate
        if burst < min_burst:
            continue
```

**讲解**（min_burst 默认 3.0）：
- 候选门槛：长度<=6字、含汉字/字母/数字（排除纯标点）、频次>=3
- `burstiness = (峰值窗口内条数 / 窗口秒数) ÷ (总条数 / 全片时长)`
  = **峰值窗口密度 ÷ 全片平均密度**
- 用"苦的"实测：峰值30s内8条 -> 密度0.267条/s；全片20条/1529s -> 0.013条/s；
  burst=20.4 倍 -> 反应词
- `avg_rate` 的分母用**全片时长**而不是词自己的跨度（见踩坑记录2）

## 5. 运行逻辑

```
manage.py shell 里调 analyze_danmaku("BV号")
   -> _load_records 读库 -> records
   -> duration_sec = 最后一条弹幕的秒数
   -> window_sec = adaptive_window(duration_sec)
   -> hot_segments_v2(records, duration_sec)   # 高能片段
   -> auto_reaction_words(records, duration_sec) # 反应词
   -> 组装 result 写 data/out/danmaku/{bvid}.json
```

关键参数：`z_thresh=2.0`（越高片段越少越精）、`merge_gap_sec=None`（默认半窗口）、
`min_burst=3.0`（反应词扎堆门槛）、`top_k=3`、`top_n=20`

## 6. 验证结果（BV15BuR6MEeR：1369 条 / 1529s）

- `window_sec=30`；高能片段 `[0-90s]`(123条) / `[120-150s]`(41条)，均带佐证弹幕
  （如 `666`、`ok哥：收了收了`）
- 反应词 Top：苦的(20)、收了收了(18)、666(16)、空瓶(14)、占领空屏(13)
- 边界用例：空数据->`[]`；完全均匀弹幕->无高能无反应词；
  3 分钟短视频->自动用 15s 窗口找到 60-75s 的"666"爆发

## 7. 踩坑记录

1. **25 分钟视频被分到 60s 窗口太粗**，开头 3 分钟糊成一段
   -> 把 30s 档从 20 分钟放宽到 30 分钟
2. **burstiness 基准选错**：第一版用"词自己的时间跨度"当平均密度基准，
   "666"15 次全挤在 14 秒内反而算出≈1 被排除（最典型的反应词！）
   -> 改用**全片时长**做基准，只存在于爆发中的词也能被识别
